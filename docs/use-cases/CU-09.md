# CU-09: Modificar información de una cuenta

| Campo | Descripción |
|---|---|
| Actor | Usuario |
| Objetivo | Actualizar la información de una cuenta propia. |
| Precondiciones | El usuario está autenticado y la cuenta existe. |
| Resultado esperado | Los cambios quedan registrados en la cuenta propia. |
| Requerimientos | Objetivo: RF-23. Reglas transversales: RF-01, RF-02, RF-03, RF-13. |

## Flujo principal

- **CU-09.1:** El usuario identifica la cuenta y los datos que desea modificar.
- **CU-09.2:** El sistema valida la autenticación, comprueba que la cuenta pertenezca al usuario y que el actor no actúe como administrador.
- **CU-09.3:** El usuario proporciona los nuevos valores.
- **CU-09.4:** El sistema registra los cambios en la información de la cuenta.

Finalización: se conservan los cambios de la cuenta.

## Flujos de excepción

### CU-09.E1: Acceso denegado

Desencadenante: paso **CU-09.2**, cuando el actor no está autenticado, actúa como administrador o no es propietario de la cuenta.

- **CU-09.E1.1:** El sistema deniega la operación sin revelar información de cuentas ajenas.
- **CU-09.E1.2:** El sistema registra el intento de acceso denegado en los logs.

Continuación: Finaliza el caso sin realizar la operación solicitada.

## Consideraciones

- Los campos modificables y las restricciones de modificación aún no están definidos.
- Se aplican los [comportamientos compartidos de acceso, auditoría y logs](../use-cases.md#comportamientos-compartidos), según corresponda a la operación.

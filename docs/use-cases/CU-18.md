# CU-18: Asignar o modificar el orden de presentación de los movimientos

| Campo | Descripción |
|---|---|
| Actor | Usuario |
| Objetivo | Establecer el orden de presentación de los movimientos de una cuenta propia. |
| Precondiciones | El usuario está autenticado y la cuenta existe. |
| Resultado esperado | Los movimientos se presentan en el orden asignado por el usuario. |
| Requerimientos | Objetivo: RF-14. Reglas transversales: RF-01, RF-02, RF-03, RF-13. |

## Flujo principal

- **CU-18.1:** El usuario indica la cuenta cuyo orden de movimientos desea establecer o modificar.
- **CU-18.2:** El sistema valida la autenticación, comprueba que la cuenta pertenezca al usuario y que el actor no actúe como administrador.
- **CU-18.3:** El usuario indica el orden de presentación deseado.
- **CU-18.4:** El sistema conserva el orden indicado y entrega los movimientos según ese orden.

Finalización: el orden de presentación queda asignado.

## Flujos de excepción

### CU-18.E1: Acceso denegado

Desencadenante: paso **CU-18.2**, cuando el actor no está autenticado, actúa como administrador o no es propietario de la cuenta.

- **CU-18.E1.1:** El sistema deniega la operación sin revelar información de cuentas ajenas.
- **CU-18.E1.2:** El sistema registra el intento de acceso denegado en los logs.

Continuación: Finaliza el caso sin realizar la operación solicitada.

## Consideraciones

- El formato para especificar el orden y el criterio usado antes de asignarlo no están definidos. No se modifica la fecha de los movimientos al ordenar su presentación.
- Se aplican los [comportamientos compartidos de acceso, auditoría y logs](../use-cases.md#comportamientos-compartidos), según corresponda a la operación.

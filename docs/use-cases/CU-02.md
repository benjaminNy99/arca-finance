# CU-02: Iniciar sesión

| Campo | Descripción |
|---|---|
| Actor | Usuario/Administrador |
| Objetivo | Obtener acceso autenticado al sistema. |
| Precondiciones | El actor dispone de un usuario registrado. |
| Resultado esperado | El actor queda identificado y autenticado. |
| Requerimientos | Objetivo: RF-01. Reglas transversales: RF-13. |

## Flujo principal

- **CU-02.1:** El actor solicita acceder al sistema y proporciona los datos de identificación y autenticación.
- **CU-02.2:** El sistema comprueba la identificación y autenticación del actor.
- **CU-02.3:** El sistema habilita el acceso autenticado y registra el resultado del intento en los logs.

Finalización: el actor queda autenticado.

## Flujos de excepción

### CU-02.E1: Autenticación no válida

Desencadenante: paso **CU-02.2**, cuando el sistema no puede autenticar al actor con los datos proporcionados.

- **CU-02.E1.1:** El sistema deniega el acceso.
- **CU-02.E1.2:** El sistema registra el intento fallido de autenticación en los logs, sin incluir credenciales.

Continuación: Finaliza el caso sin habilitar el acceso.

## Consideraciones

- No se establece un mecanismo técnico de autenticación ni reglas de contraseñas, recuperación o bloqueo.
- Se aplican los [comportamientos compartidos de acceso, auditoría y logs](../use-cases.md#comportamientos-compartidos), según corresponda a la operación.

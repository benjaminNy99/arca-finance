# CU-01: Registrar usuario

| Campo | Descripción |
|---|---|
| Actor | Usuario |
| Objetivo | Registrar un usuario en el sistema. |
| Precondiciones | No se han definido precondiciones específicas para el registro. |
| Resultado esperado | El usuario queda registrado. |
| Requerimientos | Objetivo: RF-18. Reglas transversales: RF-13. |

## Flujo principal

- **CU-01.1:** El usuario solicita su registro.
- **CU-01.2:** El usuario proporciona su nombre de usuario y contraseña.
- **CU-01.3:** El sistema registra al usuario.

Finalización: el usuario queda registrado y termina la operación.

## Campos obligatorios

| Campo | Propósito |
|---|---|
| Nombre de usuario | Debe ser único en el sistema. Comprobar si existe un usuario con el mismo nombre de usuario|
| Contraseña | Autenticar al usuario. El sistema conserva su hash, sin guardar la contraseña en texto plano. |

## Reglas de validación

| Campo | Reglas |
|---|---|
| Nombre de usuario | Quitar los espacios de los extremos y convertir las letras ASCII a minúsculas. Exigir entre 3 y 32 caracteres: letras `a-z`, números `0-9`, guion o guion bajo. Comprobar si existe un usuario con el mismo nombre normalizado; si existe, rechazar el registro. |
| Contraseña | Exigir entre 15 y 128 caracteres Unicode, conforme al módulo `password`. Los espacios cuentan como caracteres. No recortar, cambiar mayúsculas ni truncar el valor ingresado. |

La comprobación de unicidad se realiza mediante el almacenamiento durante el registro. La entidad aplica las validaciones de los datos que recibe.

Si una validación falla, informar el motivo y finalizar la operación sin registrar al usuario. El hash se genera a partir de la contraseña que superó la validación.

## Consideraciones

- La forma de habilitar el acceso queda pendiente de definir.
- Se aplican los [comportamientos compartidos de acceso, auditoría y logs](../use-cases.md#comportamientos-compartidos), según corresponda a la operación.
